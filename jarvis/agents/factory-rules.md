# Agent Factory Rules

## When Jarvis Should Create A New Agent

Create or propose a specialized agent when:

- the work repeats often;
- the work needs a distinct skill set;
- the work has measurable business value;
- the task would distract Jarvis from coordination;
- a new business or cashflow stream needs its own operating loop.

## When Jarvis Should Not Create An Agent

Do not create an agent when:

- the task is one-off and simple;
- the goal is vague;
- there is no KPI;
- the agent would require secrets or paid accounts without Giuseppe;
- it would create noise instead of cashflow.

## Required Agent Fields

Every agent must have:

- name;
- mission;
- business objective;
- owner;
- inputs;
- outputs;
- tools needed;
- permissions;
- KPI;
- quality gate;
- escalation rules;
- review frequency;
- stop condition.

## Optimization Loop

Every agent should be reviewed with:

1. What did it produce?
2. Did it create measurable value?
3. What bottleneck appeared?
4. What should be improved?
5. Should it continue, pause, or scale?

## Safety

Agents do not get unlimited authority.

They can prepare, analyze, draft, and recommend by default.

They need explicit approval for:

- paid actions;
- account changes;
- credentials;
- destructive operations;
- publishing to production unless the workflow already authorizes it.
